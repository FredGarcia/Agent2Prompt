# Propositions de l'observatoire

Ce dossier reçoit les propositions que l'[observatoire](../../specs/observatoire/SKILL.md) tire, sur le poste d'un développeur, de la confrontation des instances de ses systèmes : un retour, une proposition qu'une instance a retenue pour une spécification ; une récurrence, un même motif relevé dans plusieurs instances ; un invariant, un même invariant du dépôt cité par les écarts de plusieurs systèmes ou de plusieurs instances, proposé à la spécification qui le définit ; ou un faux refus, une règle de l'acceptable déclarée infondée par des faux refus dans plusieurs instances, proposée, trop large, à la spécification qui la définit. Chacune entre par une pull request que le développeur ouvre ; la ratification la décide, et elle ne change une spécification que par une version publiée, selon `EVOLUTION.md`.

Chaque proposition est un fichier Markdown dont l'en-tête suit le format `observatoire.proposition/1` (module [`propositions`](../../specs/observatoire/modules/propositions/SKILL.md)) : un système et ses versions, une sorte, un motif, une profondeur, des nombres, des références tronquées et un statut ; pour un invariant ou un faux refus, l'invariant et les systèmes qui l'ont relevé, des identifiants du dépôt. Aucune donnée d'une instance n'y entre, ni texte de ticket, ni code, ni chemin, ni clé, ni nom : les journaux et le magasin de l'observatoire restent sur le poste.

Statuts : `ouverte`, quand la proposition entre ; `ratifiee`, avec `version`, la version du système qui la porte, et `pr`, le numéro de la pull request ; `refusee`, avec `pr`. La pull request de ratification inscrit le statut ; l'observatoire suit ensuite l'effet des propositions ratifiées dans les enveloppes des versions qui les portent.
